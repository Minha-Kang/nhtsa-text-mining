# 모델 담당자는 무엇부터 하면 되나요?

**과거 신고 정보 X로, 다음 6개월의 공식 리콜 기록 여부 y를 맞히는 모델을 만들면 됩니다.**
데이터 준비는 끝났으며, 예측 모델 자체는 아직 학습하지 않았습니다.

처음이면 [전체 설명](README.md)과 [라벨링 설명](LABELING_GUIDE.md)을 먼저 읽어 주세요.

## 1. 모델이 풀 문제

한 행은 브랜드(MAKE)·모델·연식·기준 월입니다.

- X: 기준 월까지 접수된 신고의 수, 증가율, 사고·화재 관련 값, 증상별 건수, 글의 숫자 표현 등 415개 특징.
- y: 그다음 6개 달에 같은 차량 키의 공식 리콜 캠페인 보고 접수 기록이 있으면 1, 없으면 0.
- 결과를 정할 수 없는 행: NULL. 학습·평가에서 제외합니다.

**이 y는 과거 기록을 확인해 만든 값입니다. 미래를 예측해서 생성한 값이 아닙니다.**
특정 신고나 VIN의 실제 리콜 여부, 특정 증상이 리콜을 일으켰는지를 판정하는 모델도 아닙니다.

## 2. 필요한 파일

| 파일 | 쓰임 |
|---|---|
| panel/model_input_monthly.parquet | 최종 X와 차량·월 식별 정보 |
| panel/model_labels_monthly.parquet | y와 결과를 정할 수 있는지에 대한 표시 |
| panel/feature_manifest.json | X로 사용하도록 정한 열 목록 |
| load_model_data.py | 연결·분할·사용 가능한 y 필터를 적용하는 읽기 코드 |

model_input_monthly_base.parquet는 텍스트를 합치기 전의 중간 결과입니다. **최종 입력은 model_input_monthly.parquet**입니다.

## 3. 일단 읽어 보기

전체 데이터 ZIP을 푼 폴더를 Python 3.12 작업 폴더로 엽니다.

```bash
python -m pip install -r requirements.txt
python load_model_data.py
```

```python
from load_model_data import iter_model_batches

batches = iter_model_batches("train", batch_size=50_000)
try:
    metadata, X, y = next(batches)
    print(X.shape)
    print(y.value_counts())
finally:
    batches.close()
```

metadata는 브랜드·모델·연식·월·분할 정보입니다. X는 허용 목록의 입력 특징, y는 과거 결과입니다.
이 코드는 첫 묶음을 읽는 예시일 뿐 학습을 실행하지 않습니다. 전체 자료가 크므로 모두 한 번에 pandas에 넣기보다 묶음으로 읽으세요.

## 4. 시간 순서를 지켜서 사용하기

| 구간 | 기준 월 | 용도 | 사용 가능한 y 행 수 |
|---|---|---|---:|
| train | 1995-01~2018-12 | 모델을 학습 | 3,960,851 |
| validation | 2020-01~2021-12 | 모델 설정과 판단 기준 선택 | 645,038 |
| test | 2023-01~2026-02 중 y가 유효한 행 | 마지막 성능 평가 | 1,134,889 |

2019년과 2022년은 구간 사이 간격으로 남겼습니다. gap 행은 모델 학습·평가에서 제외합니다.
입력 표에는 2026년 8월까지 있지만, 2026년 3월 이후 기준 행은 미래 6개월을 다 확인할 수 없어 y가 NULL입니다. 차량명 등이 불확실한 행도 제외합니다. 제공한 로더가 이를 처리합니다.

행을 무작위로 섞어 학습·테스트를 다시 나누지 마세요. 결측 대치, 스케일링, 추가 특징 선택도 훈련 자료에서 기준을 정한 뒤 나머지 구간에 적용해야 합니다.

## 5. X에는 무엇이 들어 있나요?

- 이번 달 신고 수, 전월 신고 수, 최근 3·6·12개월 신고 수와 증가율
- 사고·화재·부상·사망 관련 신고 건수와 값이 알려진 신고 중 비율
- 값이 알려진 신고의 평균 주행거리
- 23개 증상 규칙별 신고 건수
- 16개 토픽과 32차원 SVD의 월별·최근 기간 평균
- 결측·본문 충돌·과거 자료가 짧은 경우를 나타내는 정보

최근 3·6·12개월 계산에는 기준 월도 포함합니다. 미래 신고는 넣지 않습니다.
신고가 없는 달은 0건으로 유지합니다. 평균이나 비율의 분모가 없으면 NULL입니다. **NULL을 전부 0으로 바꾸지 마세요.**

사고 비율은 ‘값을 알 수 있는 신고 중 사고 신고 비율’이지 전체 운행 차량의 사고율이 아닙니다. 판매량·운행 대수는 없습니다.

## 6. 텍스트마이닝이 도움 되는지 확인하기

같은 시간 분할과 평가 기준을 유지하고 다음 입력을 비교하면 됩니다.

1. 신고 수·증가율·사고 관련 값 등 기본 특징만 사용
2. 기본 특징에 증상 분류 건수를 추가
3. 여기에 토픽·글의 숫자 표현까지 추가

성능 차이를 보면 텍스트 특징의 기여를 설명할 수 있습니다.
리콜 기록이 없는 행이 많으므로 정확도 하나만 보고 판단하지 말고 정밀도·재현율·PR-AUC와 경보 건수도 함께 확인하세요. 모델과 판단 기준은 검증 구간에서 고르고, 테스트 구간은 최종 평가에 사용합니다.

## 7. 입력에 넣으면 안 되는 것

y, target_로 시작하는 열, 미래 캠페인 번호·날짜·개수, 리콜 키 일치 여부, 이전 후보 연결의 _link_ 열, 리콜 설명문을 X에 넣지 마세요. 답을 미리 보여주는 문제가 생길 수 있습니다.

제공 로더는 feature_manifest.json의 목록만 X로 읽습니다. 목표 파일 전체를 임의로 입력에 합치지 마세요.

## 8. 결과 해석에서 기억할 점

증상 규칙은 자동으로 찾은 문장 근거이며 전문가가 확정한 원인이 아닙니다. 미분류는 정상이라는 뜻이 아닙니다.
16개 토픽은 탐색 설정이며 최적 개수 검증을 마친 값은 아닙니다.
SVD 32차원은 글을 압축한 표현이며 설명 분산 합은 약 6.9%입니다. 전체 TF-IDF 희소행렬도 별도로 제공합니다.

TF-IDF는 2018년 말까지의 적격 글 1,083,019건, NMF·SVD는 그중 150,000건을 사용해 적합했습니다. 완성된 변환기는 전체 신고에 적용했습니다. 더 이른 시점부터 순차 평가하려면 당시 훈련 범위에 맞춰 변환기부터 다시 적합해야 합니다.

현재 스냅샷에는 과거 자료의 수정이 포함될 수 있습니다. 접수일·추가일을 이용한 날짜가 실제 과거 공개일을 보장하지는 않습니다. y=0도 자료의 완전성이나 결함 없음을 보장하지 않습니다.
