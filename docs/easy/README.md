# 이 데이터는 무엇이고, 어떻게 쓰나요?

**과거 신고를 정리하고, 그 뒤 실제로 리콜 기록이 있었는지 확인해 만든 학습용 데이터입니다. 아직 미래를 예측한 결과는 아닙니다.**

우리가 만들려는 모델은 이런 질문에 답합니다.

> 이번 달까지 접수된 신고를 보면, 같은 브랜드·모델·연식에 앞으로 6개월 안에 공식 리콜 기록이 생길 가능성이 얼마나 될까?

## 1. X와 y부터 이해하기

| 이름 | 쉬운 뜻 | 우리 데이터에서의 내용 |
|---|---|---|
| X | 모델에게 보여줄 정보 | 이번 달까지 신고가 몇 건인지, 얼마나 늘었는지, 어떤 증상이 적혀 있는지 등 |
| y | 모델이 맞혀야 할 과거 결과 | 그다음 6개월에 같은 브랜드·모델·연식의 공식 리콜 접수 기록이 있었는지 |

설명용 가상 예시입니다.

- 2025년 1월 말까지 A모델 2020년식에 신고 30건, 시동 꺼짐 관련 신고 12건이 접수됐습니다. 이것이 **X**입니다.
- 실제 과거 기록을 확인하니 2025년 2~7월에 그 모델·연식의 공식 리콜 접수 기록이 있었습니다. 그러면 **y=1**입니다.
- 정해진 기간을 확인할 수 있고 일치하는 기록이 없다면 **y=0**입니다.
- 아직 6개월이 다 지나지 않았거나 차량 정보가 불확실하다면 **y는 빈값(NULL)**입니다.

**예측해서 y를 붙인 것이 아닙니다. 이미 지나간 기간의 기록을 확인해서 붙였습니다.**
모델 담당자는 과거 X와 y를 함께 보며 모델을 학습시킨 뒤, 아직 결과를 모르는 미래에 X만 넣어 예측합니다.

## 2. 한 행은 무엇을 뜻하나요?

한 행은 **같은 브랜드·모델·연식의 한 달**입니다. 신고 한 건이나 차량 한 대가 아닙니다.

여기서 브랜드는 원자료의 MAKE입니다. 예를 들어 같은 모델이라도 연식이 다르거나 기준 월이 다르면 별도 행입니다. 신고가 없던 달도 포함했습니다.

## 3. 라벨링은 두 가지를 했습니다

| 작업 | 붙인 내용 | 어디에 쓰나 |
|---|---|---|
| 신고 글의 증상 분류 | 시동 꺼짐, 제동 불량 같은 증상 이름 | 월별로 세어서 X를 만드는 데 사용 |
| 과거 리콜 기록 확인 | 다음 6개월에 공식 기록이 있으면 1, 없으면 0, 판단 불가면 NULL | 모델이 맞혀야 할 y |

**시동 꺼짐으로 분류됐다고 리콜 y가 1이 되는 것은 아닙니다.**
자세한 예시는 [라벨링 쉬운 설명](LABELING_GUIDE.md)에 있습니다.

## 4. 지금까지 끝낸 일

신고 글 정리 → 23가지 증상 규칙 적용 → 16개 토픽과 글의 숫자 표현 생성 → 차량 그룹별 월별 집계 → 과거 리콜 기록으로 6개월 y 생성까지 했습니다.

- 신고 1,603,647건 모두에 처리 결과 또는 사용 불가 이유를 남겼습니다.
- 월별 집계에는 조건을 충족한 신고 1,579,767건을 사용했습니다.
- 완성된 월별 표는 6,597,714행이며, X에 쓸 특징은 415개입니다.
- 증상 규칙은 전문가 진단이 아니며, 16개 토픽도 확정된 고장 종류가 아닙니다.
- 리콜을 예측하는 모델 자체는 아직 학습하지 않았습니다.

## 6. 가장 중요한 해석

**y=1은 같은 브랜드·모델·연식에 공식 리콜 기록이 있다는 뜻입니다. 그 그룹의 모든 신고나 모든 차량이 실제 리콜 대상이었다는 뜻은 아닙니다.** y=0도 차량에 결함이 없다는 뜻이 아닙니다.

신고 번호와 리콜 번호를 직접 연결하는 공통 신고 키는 없습니다. 이전 버전의 ‘관련 리콜 후보’를 정답으로 바꾼 것이 아닙니다.

현재 자료의 관측 기준일은 **2026-08-31**입니다. 2026년 3월 이후 기준 행은 다음 6개 달을 이 기준일까지 전부 확인할 수 없어 y가 비어 있습니다. 오늘 날짜가 지나갔다고 기존 파일의 y가 자동으로 갱신되지는 않습니다.
