# 모델 담당자 인수인계

## 이번에 끝낸 범위

원본 보존과 텍스트 정제에 이어, 고장 증상 자동 주석·토픽 모델링·텍스트 벡터화·월별 특징 생성·6개월 리콜 목표 생성을 완료했습니다. 자동 증상 주석은 규칙 기반 약한 라벨이며, 예측 모델은 아직 학습하지 않았습니다.

신고 단위 결과는 1,603,647건 모두를 유지합니다. 월별 집계에는 차량 키와 사용 가능 날짜 등을 충족하는 1,579,767건을 사용했습니다. 전체 차량 그룹 31,731개에 대해 첫 신고 월부터 2026년 8월까지 달력을 채워 6,597,714행을 만들었습니다. 신고가 없는 달 6,009,463행도 포함합니다. 제외 사유는 `panel/complaint_eligibility.parquet`에 남아 있으며, 개별 제외 사유의 건수는 서로 겹칠 수 있습니다.

## 반드시 구분할 세 가지

1. **기존 신고–리콜 후보 연결:** 차량 조건·부품·설명문 유사성으로 찾은 참고 관계입니다. `odi_number`와 `CAMPNO`를 직접 연결하는 공통 신고 키가 없으므로, 특정 신고가 실제 리콜됐다는 정답으로 사용하면 안 됩니다.
2. **23개 고장 증상 규칙 결과:** 신고 문장에 특정 증상을 뒷받침하는 표현이 있는지 표시합니다. 실제 기계적 원인을 확정한 전문가 판정은 아닙니다. 복수 유형이 가능하고, 미분류는 정상이라는 의미가 아닙니다.
3. **이번 `y_recall_6m`:** 동일 제조사·모델·연식의 공식 차량 리콜 캠페인 접수 기록이 다음 6개 달에 존재하는지 나타내는 그룹 수준의 목표입니다. 개별 신고·VIN의 대상 여부나 고장 유형별 인과관계는 보장하지 않습니다.

리콜 자료가 곧 개별 신고의 정답이 되는 문제는 이번 처리로도 해결되지 않습니다. 대신 예측 단위를 명확하게 **차량 그룹·월**로 정해, 공식 기록에서 계산 가능한 목표를 만들었습니다.

## 6개월 목표의 정확한 정의

이 문서에서 '제조사'는 원자료의 **브랜드(MAKE, `MAKETXT`) 키**를 뜻합니다. 법인 제조사 이름인 `MFR_NAME`으로 연결한 것이 아닙니다.

입력 기준일은 각 달의 마지막 날입니다. `month_end < RCDATE <= 다음 여섯 번째 달의 마지막 날`이면 `y_recall_6m=1`입니다. `RCDATE`는 NHTSA 공식 캠페인의 보고 접수일이며 최초 고장일·언론 발표일·수리 완료일을 뜻하지 않습니다. 동일 차량 키의 같은 `CAMPNO`가 여러 부품 행으로 반복되어도 한 캠페인으로 셉니다.

예를 들어 2025-01-31의 목표 구간은 2025-02-01~2025-07-31입니다. 2026-02-28의 목표 구간은 2026-03-01~2026-08-31입니다. 180일로 계산하지 않습니다.

| y 값 | 해석 |
|---|---|
| 1 | 정의한 차량 키와 기간에 공식 캠페인 접수 기록이 존재 |
| 0 | 기간 끝이 관측 기준일 이내이며, 정확한 키로 일치하는 공식 캠페인 기록이 없음 |
| NULL | 미래 6개월이 관측 기준일을 넘거나, 차량명 등 목표 계산에 불확실성이 있음 |

관측 기준일은 다운로드 스냅샷 직전의 마지막 완결 월인 **2026-08-31**로 설정했습니다. 따라서 **2026년 3월 이후 기준 행은 목표를 NULL로 유지**합니다. 일부 미래 구간에서 이미 리콜을 발견했더라도 같은 기준으로 전부 검열합니다. 0은 결함이 없거나 안전하다는 뜻이 아니며, 자료가 완벽하게 수집됐다는 보장도 아닙니다.

차량명은 보수적으로 정규화한 제조사·모델·연식을 정확히 일치시킵니다. 정확히 일치하지 않지만 공백·하이픈을 제거하면 후보가 있는 114개 키는 `unresolved_vehicle_name`으로 두고 목표를 NULL로 처리했습니다. 단순 후보 연결로 양성 정답을 만들지 않았습니다. 압축 키 후보조차 없는 11,844개 키에는 문자 그대로의 '일치 기록 없음' 기준이 적용되지만, 발견하지 못한 명칭 차이로 생기는 누락은 남을 수 있습니다.

이 목표는 **모든 부품을 포괄하는 차량 그룹 리콜**입니다. `failure_mode_monthly.parquet`에 같은 y를 붙여 특정 고장 유형의 확정 정답이라고 부르면 안 됩니다. 유형별 리콜 예측으로 목표를 좁히려면 부품·유형 대응 규칙과 검증을 별도 정의해야 합니다.

## 텍스트를 어떻게 처리했는가

초기 정제는 원문과 여러 버전을 보존하면서 HTML 엔티티, 줄바꿈 태그, 유니코드, 제어 문자와 공백을 정리했습니다. 부정 표현과 숫자를 없애거나 결측을 임의의 0/N으로 채우지 않았습니다. 동일 신고의 본문이 충돌하는 경우도 표시했습니다. 기존 원문·정제문은 이전 패키지에 있습니다.

이번 특징용 복사본에서는 영어 축약 부정 표현을 풀고 소문자·단어 및 두 단어 조합으로 TF-IDF를 계산했습니다. `no`, `not`, `never`, `without` 등은 유지하고 반복 행정 표현·불용어를 특징에서 제외했습니다. 본문 전체가 '요약 없음' 같은 자리표시 문구인 경우 특징 생성에서 제외했습니다. 원문 자체는 바꾸지 않았습니다.

TF-IDF 단어 사전과 IDF는 **2018-12-31까지의 적격 신고 1,083,019건**에만 적합했습니다. 그중 고정 난수로 뽑은 150,000건에 NMF 16개 토픽과 SVD 32차원을 적합하고, 이후 자료는 이미 적합된 변환기로 변환했습니다. 리콜 설명문이나 y를 이 학습에 사용하지 않았습니다. 표본 ID와 사용 날짜를 별도 파일로 보존했습니다.

SVD는 TF-IDF를 압축한 표현이며 사전학습 언어모델 임베딩이 아닙니다. 32차원 설명 분산 합은 약 **6.9%**로, 텍스트 정보를 많이 압축합니다. 이를 유일한 텍스트 표현으로 강제하지 않도록 전체 30,000열 TF-IDF도 희소행렬로 제공합니다. `row_index.parquet`를 사용해 문서와 행을 연결해야 합니다.

최종 텍스트 상태는 유효 벡터 1,584,590건, 본문 충돌 13,144건, 자리표시 문구 5,190건, 사전 밖 문서 709건, 빈 본문 14건입니다. 사용 불가 벡터는 0으로 두되 별도의 마스크를 제공합니다. **0 벡터를 정상 차량이나 평균적인 내용으로 해석하면 안 됩니다.**

23개 증상 규칙은 모든 가용 본문 버전에 적용해 근거를 남겼습니다. 572,867건에 하나 이상이 매칭됐으며, 전문가 정답셋으로 정확도를 측정한 것은 아닙니다. 증상 예측 특징은 `nlp_usable=1`이고 본문 충돌이 없는 신고만 집계하며, 토픽·SVD 평균은 벡터 유효성도 확인합니다. 전체 신고 수 등 기본 특징은 본문 상태만으로 신고를 제외하지 않습니다. 분석용 증상 표에는 충돌 포함 건수와 예측 입력에 적격인 건수가 별도로 있습니다. [고장 증상 설명](failure_modes/FAILURE_TYPES_KO.md)과 [토픽 검토](text_features/TOPIC_REVIEW.md)를 함께 확인하십시오.

## X를 구성하는 정보

입력 특징은 **415개**이며, 정확한 목록은 `panel/feature_manifest.json`의 `feature_columns`입니다. `model_input_monthly_base.parquet`는 중간 산출물이고, 최종 모델 입력은 **`model_input_monthly.parquet`**입니다.

월별 신고 수, 전월·최근 3/6/12개월 신고 수와 증가율, 사고·화재·부상·사망 언급 수와 알려진 값의 분모, 주행거리 평균, 결측·충돌 수, 23개 증상 근거 수, 16개 토픽·32차원 SVD 평균을 제공합니다. 최근 구간은 현재 월을 포함합니다. 텍스트의 구간 평균은 월별 평균을 단순 평균한 값이 아니라 유효한 신고 수로 가중한 전체 신고 평균입니다.

0건인 달은 달력에 포함하며, 알려진 분모가 0인 비율·평균·증가율은 NULL로 둡니다. 사고 비율은 값을 알 수 있는 **신고 중 비율**입니다. 판매·운행 차량 수가 없으므로 실제 차량의 사고율·고장률로 해석하면 안 됩니다.

각 월에는 `availability_date_proxy=max(received_date,date_added)`가 해당 월 말 이내인 신고만 포함합니다. 날짜 충돌·필수 날짜 없음·미래 날짜 플래그 등은 집계 제외 사유로 남깁니다. 증상별 분석 표는 유형이 처음 관측된 시점 이후의 달을 다루며, 실제 격자 형태는 `panel/integration_manifest.json`에 기록되어 있습니다.

## 학습·검증·테스트 사용법

| split | 입력 기준 월 | y=1 | y=0 | 학습·평가에 쓰는 합계 |
|---|---|---:|---:|---:|
| train | 1995-01~2018-12 | 106,344 | 3,854,507 | 3,960,851 |
| validation | 2020-01~2021-12 | 14,976 | 630,062 | 645,038 |
| test | 2023-01~2026-02의 목표 유효 행 | 26,734 | 1,108,155 | 1,134,889 |

2019년과 2022년은 경계 간격을 확보한 `gap`으로 보존하고 학습·평가에서는 제외합니다. 테스트 입력 표에는 2026년 8월까지 존재하지만, 6개월을 관측할 수 없는 행의 y는 NULL입니다. 차량명 불확실 행도 제외합니다. 양성 비율이 낮으므로 모델 담당자는 불균형과 시간 순서를 고려해 평가 방법을 정해야 합니다.

`load_model_data.iter_model_batches()`는 지정 split에서 유효한 y가 있는 행만 읽고, 허용 목록의 수치 X와 메타데이터를 분리합니다. 메타데이터에는 제조사·모델·연식·월·split이 들어 있습니다. 문자열을 임의의 정수로 바꿔 자동 포함하지 않았으며, 차량명 인코딩이 필요하면 훈련 구간에서 별도 적합해야 합니다.

**입력 금지:** y 열, `target_*`, 캠페인 날짜·번호·개수, 리콜 키 일치 여부, 과거 후보 연결의 `_link_*`, 리콜 설명문. 목표 계산·진단용 파일을 X에 통째로 병합하지 마십시오. 결측 대치, 스케일링, 추가 특징 선택도 훈련 자료에만 적합하십시오.

현재 변환기는 고정 분할용으로 2018년 말까지의 텍스트로 적합했습니다. 더 이른 시점을 기준으로 순차 재학습 평가를 하려면 각 당시의 훈련 범위에 맞춰 텍스트 변환기부터 다시 적합해야 합니다.

## 검증 및 남아 있는 한계

독립 검증은 신고 ID 보존, 입력 허용 열, 공식 리콜 날짜와 6개월 경계, 검열·분할, 월별 벡터·증상 집계와 구간 평균을 대조합니다. TF-IDF는 33개 조각의 전체 1,603,647행에 대해 원본 ID 순서·마스크·정규화·희소행렬 형태·단어 사전을 확인합니다. 증상 규칙의 부정 표현 점검과 실제 근거 표본 검토도 수행했습니다. 상세 범위와 결과는 각 JSON 보고서에 있습니다.

이 검증은 계산·데이터 연결 검증이며 고장 분류의 실측 정확도나 리콜 예측 성능 검증은 아닙니다. 현 스냅샷의 과거 본문·필드 수정은 과거 공개 당시 상태와 다를 수 있습니다. `availability_date_proxy`가 실제 공개일을 보장하지 않습니다. NHTSA의 과거 시스템 이전에서 일부 결측이 0/N으로 바뀐 경우 원래 결측 여부를 복원할 수 없습니다. 같은 차량이 반복되는 월별 표의 특성, 장기간 운행 여부를 알 수 없는 문제도 모델 해석에 반영해야 합니다.

모델 담당자가 이어서 할 일은 이 정의를 바탕으로 훈련 구간에서 모델·결측 처리·튜닝을 정하고, 검증 구간에서 선택한 뒤 테스트 구간에서 성능을 평가하는 것입니다. 특정 고장 유형이나 개별 차량 대상 여부로 연구 질문을 바꾸는 경우에는 현재 y의 이름만 바꾸지 말고 목표 정의부터 수정해야 합니다.
