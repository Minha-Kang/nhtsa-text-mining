# 월별 표는 어떻게 읽나요?

**같은 브랜드·모델·연식의 신고를 한 달씩 묶은 표입니다.** 신고 한 건에 리콜 정답을 붙인 표가 아닙니다.

## X와 y가 따로 있습니다

- model_input_monthly.parquet: 이번 달까지 알 수 있는 정보 X
- model_labels_monthly.parquet: 과거 기록에서 확인한 다음 6개월의 결과 y
- 연결 기준: make_key, model_key, model_year, month_end

처음에는 직접 병합하기보다 상위 폴더의 load_model_data.py를 쓰면 됩니다.

## 가상 예시

2025년 1월 말 기준 A모델 2020년식의 최근 신고가 늘고 시동 꺼짐 문구가 자주 등장했습니다. 그 정보가 X입니다.
실제 2025년 2~7월 공식 기록에 같은 차량 키의 리콜 캠페인이 있으면 y=1입니다.
글에 시동 꺼짐이 있다고 자동으로 y=1을 붙이지 않습니다.

## 신고가 없는 달도 포함합니다

첫 적격 신고가 나온 월부터 2026년 8월까지 매달 한 행을 만듭니다. 신고가 없으면 신고 수는 0입니다.
31,731개 차량 키에 6,597,714행이 있으며 6,009,463행은 그달 신고가 없습니다.
운행 차량 전체 명부가 아니므로 한 번도 신고가 없는 차종까지 포함하는 것은 아닙니다.

## 계산 기준

신고의 접수일과 추가일 중 늦은 날짜를 사용하고, 기준 월 말까지 들어온 신고만 X에 포함합니다.
해당 날짜는 실제 과거 공개일을 보장하지는 않습니다.

최근 3·6·12개월은 현재 월을 포함해 계산합니다. 글의 평균은 유효한 신고 수로 가중한 평균입니다.
분모가 0인 평균·비율·증가율은 NULL로 유지합니다. 증상 0건은 규칙 근거가 잡히지 않았다는 뜻이며 실제 고장이 없다는 뜻은 아닙니다.

## y 읽는 법

- 1: 다음 6개 달에 정확한 브랜드·모델·연식의 공식 캠페인 접수 기록이 있음
- 0: 관측 범위 안에서 지정된 불확실성이 없고, 정확한 키로 일치하는 기록이 없음
- NULL: 기간 전체를 관측할 수 없거나 차량명·공식 날짜가 불확실함

관측 기준일은 2026-08-31입니다. 2026년 3월 이후 기준 행의 목표는 NULL입니다.
브랜드는 MAKE이며 법인 제조사 이름 MFR_NAME으로 연결한 것은 아닙니다.
모든 부품의 캠페인을 포괄하므로 y를 특정 고장 유형의 확정 정답으로 복사하면 안 됩니다.

## 나머지 파일

| 파일 | 쉬운 설명 |
|---|---|
| model_input_monthly_base.parquet | 텍스트 특징을 더하기 전의 중간 표 |
| complaint_eligibility.parquet | 각 신고가 월별 집계에 포함됐는지와 제외 사유 |
| failure_mode_monthly.parquet | 차량·증상·월별 건수. 증상이 처음 관측된 뒤 신고가 없는 달도 포함 |
| failure_mode_observed_monthly.parquet | 증상 규칙 근거가 실제로 잡힌 달만 모은 표 |
| feature_manifest.json | X로 읽어도 되는 열과 계산 기준 |
| official_campaign_products.parquet | y 계산에 쓴 공식 캠페인 기록. X에 넣지 않음 |
| target_key_coverage.parquet | 차량 이름 일치 여부를 점검한 정보. X에 넣지 않음 |
| quality_report.json | 계산·집계 확인 결과 |

증상별 월별 표는 22,983,072행입니다. 한 신고에 여러 증상이 붙을 수 있어 신고 수와 합계가 다릅니다.
